✦ How This Tool Works

What problem does this actually solve?

Firewall rules, ACLs, and route tables speak CIDR, but the address ranges you're handed — from a vendor, a cloud provider's published IP list, or an internal allocation spreadsheet — are almost always given as a start–end range. Converting that by hand into the minimal, correctly-aligned set of CIDR blocks is tedious and error-prone at scale; this tool does it exactly, in bulk, and exports it directly into the syntax your firewall or IaC tool expects.

Why would I merge overlapping or adjacent ranges first?

Lists assembled from multiple sources (say, two spreadsheets from different teams) often contain ranges that overlap or sit right next to each other. Converting each one separately produces redundant, unnecessarily numerous CIDR blocks. Merging first — combining overlapping and touching ranges into one — before summarizing produces a smaller, cleaner block list that still covers exactly the same addresses.

What does "never summarize broader than /X" actually protect against?

The minimal-CIDR algorithm will happily produce a very broad block (like a /8) if the input range and alignment allow it. Some environments intentionally cap how broad a single summarized route or ACL entry is allowed to be — for change-control, blast-radius, or route-flap-damping reasons. Setting this limit forces the algorithm to split anything broader than /X into multiple more specific blocks instead, without changing which addresses are covered.

How do exclusions work?

Exclusion ranges are subtracted from your input ranges before CIDR conversion runs. Given a broad allow rule like 10.0.0.0/16 and an exclusion of 10.0.5.0/24, the tool computes the exact remaining coverage (everything in the /16 except that one /24) and only then converts what's left into minimal CIDR blocks — the standard "allow this whole range except these specific addresses" pattern.

Is the conversion exact?

Yes. Every export format is generated from the same underlying minimal CIDR block list, computed with the standard bit-alignment summarization algorithm (the same approach routers and firewalls use internally) — so the block list, Cisco ACL, iptables rules, and AWS Security Group JSON always describe exactly the same set of addresses.

Is anything sent to a server?

No, with one exception: the "Detect My Public IP" button is opt-in and calls a third-party API (ipify.org) to look up your public IP. Everything else — parsing, merging, exclusion, CIDR summarization, and every export format — runs entirely in your browser. Your draft and settings only persist in this browser's local storage.
